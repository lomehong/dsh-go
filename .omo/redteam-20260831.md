### C3 · 会话事件馈线投递错误事件 + telemetry map 竞态

- `session/session.go:149-189`：`appending` 旗标同临界区自设自清（173/179 行）→ "重入拒绝"分支不可达，死代码；`entry.appendCommitted()`（186-188 行）锁外执行。
- `session/store.go:171`：馈线投递 `events[len(events)-1]`——读回调时刻的末尾，非触发回调的事件。并发 append 下同事件投两次、另一事件永不投递 → 持久化 write-behind 断序 → 连续性校验失败 → durability 停摆。
- `sessiontelemetry/coordinator.go:340-343`：`seen()` 返回裸 map，`track`（:259）与 `captureEvent`（:272-275 无锁 RMW）锁外并发访问 → Go runtime concurrent map 崩溃。
- r53 的"3 flake"即这些真实竞态的症状。

## 重要（10）

1. **shell 沙箱空头支票**（`sandbox/provider.go:145-147`、`shelllocal/shelllocal.go:221`、`shelltool/shelltool.go:84`）：全仓唯一 `Confine` 实现恒返 `SANDBOX_UNAVAILABLE`；`SandboxMode()` 恒空串；模型面文案仍承诺永不触发的 `[sandbox: file access denied under <mode> mode]`。read-only 预设下 `bash -c` 无任何门；升级审批参数未进 bash 参数 schema。
2. **环境清洗子串黑名单**（`subprocess/env.go:10-11`：`KEY|PASSWORD|SECRET|TOKEN`）：漏 `SSH_AUTH_SOCK`（签名能力泄漏）、`DATABASE_URL`、`GOOGLE_APPLICATION_CREDENTIALS`、`GPG_PASSPHRASE`。模型一句 `env` 即泄密进 LLM 上下文。
3. **JSON-RPC 传输无帧上限**（`sdk/protocol/transport.go:200-203`）：`ReadString('\n')` 无界 → OOM。
4. **base64 图片先解码后限额**（`attachment/admission.go:59-66`）：1.3GB base64 先分配 ~1GB 再拒。经 `session/prompt` 远程可触发。
5. **监听器 panic 杀进程**：Serial/Waterfall 派发无 recover（`agent/events.go:203-217`），驱动 goroutine 无顶层 recover。
6. **fuseDeactivation watcher 每 agent 泄漏 1-2 条 goroutine**（`agentloop/factory.go:186-213`，stop() 取消不了）。
7. **Inbox 两段锁删错消息**（`agent/inbox.go:191-215`，locate 与 Splice 间坐标过期，且持久化 `inbox/spliced`）。
8. **Store.Flush 死代码**（`session/store.go:377-419`，cleaned 永不 detach）；jobs `Read` 锁外 `readOutput()` 并发交错游标（`jobs/local.go:427-447`，F1 残留）。
9. **cmd/dsh 空壳**：组合后 `<-stop` 等 SIGINT，webserver 从未 serve，无 chat 面——"移植完成 85+"无可运行产品，集成正确性只活在测试里。
10. **账本自漂移四处**：STATUS 人工行 93/1181 vs 生成块 110/1367 vs VERIFY 1280；catalog 实际 91 键 vs 生成器 87/85 vs 文档 86。根因：`scripts/genstatus/main.go:79` 分母硬编码 85、:80-82 过滤恒真——**反漂移机制是漂移源头**。
